대상: 일본어 말하기 연습 웹앱 제작 프로젝트 (참고 사이트: wasabi123.netlify.app)

## 1. 프로젝트 개요

고등학교 일본어 수업에서 학생들이 선생님이 정한 문장을 소리 내어 연습하고, 음성인식으로 자동 채점되며, 그 점수가 선생님의 구글 스프레드시트에 누적되는 웹앱을 제작했습니다. 학생들은 회원가입 없이 학번·이름만 입력해 접속하고, Google Chrome 브라우저의 음성 인식 기능으로 발음을 인식해 정답 문장과 글자 단위로 비교한 뒤 점수를 매깁니다. 카테고리별로 문장을 순서대로 통과해 나가는 방식이며, 문제 내용과 채점 보정 사전은 이제 구글시트에서 실시간으로 관리합니다.

## 2. 주요 설계 결정

- **구글시트 연동 방식**: 참고 사이트(와사비)와 동일하게 **독립 웹사이트 + Google Apps Script** 방식을 선택했습니다. 학생이 문장을 말할 때마다 실시간으로 구글시트에 한 줄씩 기록되고, 반대로 문제 목록·채점 보정 사전도 같은 스프레드시트에서 실시간으로 읽어옵니다.
- **학생 식별 방식**: 로그인 없이 **학번 + 이름**을 입력하는 방식으로 결정했습니다.
- **문장(예문) 관리 방식**: 처음에는 Claude가 만든 기본 세트를 `questions.js` 파일로 직접 수정하는 방식으로 시작했으나, 이후 **구글시트에서 직접 관리하는 방식**으로 전환했습니다(자세한 내용은 4·7절 참고).
- **문장 진행 방식**: 자유 선택(드롭다운)에서 **카테고리별 순차 진행(80% 이상 통과해야 다음 문장으로 이동)** 방식으로 변경했습니다.

## 4. 핵심 기능

- **로그인 화면**: "다루마!!" 타이틀과 선생님이 주신 다루마 도장 이미지로 구성된 히어로 영역, 학번·이름 입력, 개인정보 저장 동의 체크, 재접속 시 자동 기억(브라우저 저장)
- **카테고리별 순차 진행**: 학생은 문장을 자유롭게 고르지 않고, 카테고리 안에서 정해진 순서대로 진행합니다. 한 문장을 80% 이상 점수로 통과해야 다음 문장이 열리고, 진행 상황은 진행률 바(`n / 전체 문장 통과`)로 표시됩니다. 카테고리를 모두 통과하면 축하 화면과 함께 "다음 카테고리로 이동" 버튼이 나타나고, 필요하면 해당 카테고리를 초기화하고 재도전할 수도 있습니다. 같은 문장에서 3회 연속 오답이 나오면 자동으로 오답 처리하고 잠시 후 다음 문장으로 넘어가, 한 문장에 막혀 계속 붙잡혀 있지 않도록 했습니다.
- **모범 발음 듣기**: 브라우저 내장 TTS(Web Speech API `speechSynthesis`, ja-JP 음성)로 정답 문장 음성을 실시간 합성해 재생합니다. 별도 음성 파일이나 유료 서비스 없이 무료로 동작하며, 브라우저·기기에 따라 음질이 다를 수 있습니다. (네이버 CLOVA Voice/파파고 계열 음성으로 교체하는 방안도 검토했으나, 교사님 명의의 네이버 클라우드 플랫폼 계정·API 키 발급이 필요해 현재는 보류하고 지금 방식을 유지하기로 했습니다.)
- **말하기 채점**: Web Speech API로 음성을 인식하고, 정답 문장과 인식된 문장을 정규화(공백·구두점 제거 + **한자→히라가나 보정**) 후 레벤슈타인 거리 기반 유사도로 점수 산출(0~100%). 기준 점수(기본 80%) 이상이면 통과, 미만이면 재도전으로 표시하며 글자 단위로 맞은 부분(초록)/틀린 부분(빨강)을 시각적으로 표시
  - **한자→히라가나 보정**: 학생이 히라가나로만 말해도 음성 인식 결과가 한자로 반환되는 경우가 많아(예: "またあした" → 인식 결과 "また明日") 오답 처리되던 문제를 해결했습니다. 채점 직전에 인식 결과와 정답 문장을 모두 같은 표기(히라가나)로 통일해서 비교합니다.
- **개인 기록 탭**: 총 연습 횟수, 평균/최고 점수, 점수 추이 그래프(캔버스), 최근 기록 목록 — 학생 브라우저에 로컬 저장
- **구글시트 실시간 전송(점수)**: 매 시도마다 Google Apps Script 웹앱으로 결과 전송(시간/학번/이름/문장/인식결과/점수/통과여부). `text/plain` + `no-cors` 방식으로 CORS 제약을 피하고, 전송 실패 시 로컬에 대기열로 저장했다가 다음 접속 시 자동 재전송
- **구글시트 실시간 불러오기(문제·채점 사전)**: 학생이 접속할 때마다 앱이 구글시트의 "문제은행"(연습 문장)과 "한자읽기"(한자→히라가나 보정 사전) 두 탭을 각각 불러옵니다. 성공하면 그 내용을 그대로 쓰고, 인터넷 문제 등으로 실패하면 각각 `questions.js`와 index.html에 내장된 기본 사전으로 자동 대체되어 학생 화면이 멈추지 않습니다.

## 7. 향후 운영 방침

문제 내용 관리 방식이 파일 편집에서 **구글시트 편집**으로 바뀌었습니다.

- **연습 문장(문제)을 추가·수정·삭제할 때는 구글 스프레드시트의 "문제은행" 탭**에서 카테고리 / 일본어 문장 / 한국어 뜻 세 칸을 편집합니다. 저장하면 학생이 다음에 접속할 때 바로 반영되고, `index.html`이나 `questions.js`를 건드리거나 Netlify에 다시 올릴 필요가 없습니다.
  - 한자에 후리가나(읽는 법)를 달고 싶으면 일본어 문장 칸에 `<ruby>漢字<rt>よみ</rt></ruby>` 형식으로 입력하면 됩니다.
- **한자→히라가나 채점 보정이 더 필요할 때는 "한자읽기" 탭**에 한자(또는 인식될 수 있는 표기) / 히라가나(정답으로 처리) 두 칸으로 한 줄만 추가하면 됩니다. 예: 새 단어 "先生"이 문제로 들어가면 "先生" / "せんせい" 행을 추가.
- `questions.js`는 지우지 말고 그대로 두세요. 인터넷 문제 등으로 구글시트를 못 불러올 때만 자동으로 대신 쓰이는 예비용입니다. 다만 구글시트 내용과는 자동으로 동기화되지 않으니(그 시점의 스냅샷), 최신으로 맞추고 싶으면 언제든 말씀해 주시면 다시 반영해 드립니다.
- `index.html`은 디자인 변경, 채점 기준(통과 점수) 변경, 새로운 기능 추가처럼 **구조적인 변경이 필요할 때만** 수정합니다.
- `AppsScript_Code.gs` 코드를 수정한 뒤에는 반드시 Apps Script 편집기에서 **[배포] > [배포 관리] > 연필 아이콘 > 새 버전**으로 다시 배포해야 변경 사항이 적용됩니다(URL은 바뀌지 않음).
- `index.html` / `questions.js` / `AppsScript_Code.gs` 등을 수정한 뒤에는 GitHub 저장소로 **git push**해야 Netlify 사이트에 반영됩니다. Claude에게 "저장해줘" / "여기까지 올려줘" / "/done"이라고 말하면 변경 내용을 요약한 커밋 메시지로 자동 커밋·push합니다. 자세한 절차는 [설정_가이드.md](설정_가이드.md)를 참고하세요.
